## 4. Correctif v6 (`e291912`) — défense en profondeur

### 4.1 Guérisseur — garde fail-closed (`.github/workflows/guerisseur-production.yml`)

- L'appel API « runs du CD » est réessayé **3× espacées de 10 s** ;
- si les 3 échouent → état **indéterminable** → **pas d'escalade ce tick**
  (renoncer à brailler une fois vaut mieux qu'un faux positif ; le tick
  suivant re-décidera) ;
- filtre élargi aux états d'attente de concurrency (`waiting`/`pending`) en
  plus de `in_progress`/`queued`.

### 4.2 CD — refermeture à la source (`.github/workflows/deploy-vps.yml`)

- Nouvelle étape **« Refermer l'escalade production ↔ main (livraison
  prouvée) »**, conditionnée STRICTEMENT au succès de `verify_build` (la
  production sert exactement ce build — deploy-info + version.json alignés) :
  l'écart prod↔main est résolu **par définition**, le CD referme l'escalade
  lui-même avec un commentaire horodaté ;
- `permissions` : ajout mesuré de `issues: write` (justifié en commentaire ;
  seule écriture d'issue du workflow) ;
- refermeture **non bloquante** (échec API de clôture = warning, jamais un run
  rouge ni un déploiement annulé) ;
- conséquence structurelle : une escalade ne survit plus à sa propre résolution
  même si TOUS les ticks cron sont perdus — l'acteur de la livraison est
  l'acteur de la refermeture.
