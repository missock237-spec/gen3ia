## 8. Enseignements

### 8.1 La passerelle générique sans consommateur : protection exemplaire, existence injustifiée

`/ai/generate` avait TOUT du code de production vertueux : Zod, rate-limit honnête, jeton de concurrence (429 honnête), billing par exécution, usage tracking. Et zéro appelant. La qualité interne ne remplace pas l'usage : une porte HTTP est un produit, pas une bibliothèque — elle se justifie par un consommateur, pas par sa robustesse. La suppression est d'autant plus sûre que la fonction sous-jacente est massivement consommée (26 import directs) : **on ne supprime jamais une capacité, seulement une porte redondante**.

### 8.2 La décision produit « en dur » dans le code vaut décision documentée

`AGENT_SYSTEM_RESERVED_MESSAGE` est une décision produit codée en dur avec son message utilisateur : la philosophie « demandez-le dans le chat » gouverne toute la surface agents. Pour le registre, ce type de constante est un **document exécutable** — il a fondé le verdict pre-ui-roadmap au même titre qu'une ligne du plan plateforme. Leçon : chercher les décisions produit dans les constantes de message (403 explicites, codes d'erreur) avant de conclure au doublon mort.

### 8.3 Deux générateurs, deux destins : le plan tranche

Même famille (génération LLM), même qualité de construction — et pourtant deux verdicts opposés. La variable décisive : **le plan plateforme mentionne l'un (UI d'acceptation LOT 3) et pas l'autre**. Le registre honnête n'est pas un jugement de valeur sur le code, c'est la lecture de la roadmap : ce qui est planifié reste (pre-ui), ce qui ne l'est pas et n'a pas d'appelant disparaît (suppression).
