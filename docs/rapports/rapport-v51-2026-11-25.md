# RAPPORT V5.1 — Ancres pondérées : routage 18 domaines à 100 % sur 1 M requêtes réelles

**Date : 2026-11-25 · Job 478451 (suite v5) · branche `main` · base `4e527f1`**

## 1. Ce qui a changé (v5.0 → v5.1)

Le routage lexical v5 attribuait des points entiers par token reconnu
(2 par mot-clé noyau, 1 par ancre enrichie). Conséquence mesurée : les
tokens partagés entre domaines (« analyse », « données », « client »,
« web », « audit »…) créaient des collisions qui plafonnaient l'accuracy
à 87,06 % sur 1 M requêtes réelles.

v5.1 remplace ce comptage entier par une **masse d'usage mesurée** :

| Élément | Contenu | Effet sur le routage |
|---|---|---|
| `POIDS_ANCRS_V51` (`lib/neural/training/ancres-ponderees-v51.ts`) | masse d'usage RÉELLE par domaine de chaque token partagé, mesurée sur les 18 datasets complets (100 000 lignes/domaine, graine 20261024, tokeniseur exact du routeur : minuscules, NFD sans diacritiques, découpage non-alphanumérique) | un token partagé ne rapporte plus 2 points entiers à chaque domaine : chaque domaine reçoit sa fraction mesurée (ex. « analyse » → sciences_humaines 0,60, analyse_donnees 0,29, hacker 0,11) |
| `NOUVEAUX_ANCRS_V51` | tokens exclusifs découverts (≤ 2 domaines, ≥ 12 occurrences, masse ≥ 0,8) absents des listes v5, extraits avec le tokeniseur exact (« pare-feu » → « pare » + « feu », corrigeant l'angle mort de l'extraction v5) | élargit la couverture (ex. cybersecurite : `mfa`, `cve`, `vpn`, `backup`…) |
| `ANCRS_CURATES_V51` | complément curaté du vocabulaire métier produit, mesuré ABSENT des instructions des datasets (provenance documentée dans `genere_ancres_ponderees.py`) | base 1 flat, insensible à la masse |
| `mots-cles-enrichis.ts` régénéré | ancres v5 recalculées avec le tokeniseur exact du routeur | supprime le décalage tokenisation extraction vs routage |
| `scripts/evaluation-1m.ts` | miroir EXACT de `predireDomaineLexical` v5.1 | l'évaluation mesure le code de production, pas une copie divergente |
| `genere_ancres_ponderees.py` — stoplist corrigée | la découverte d'ancres exclusives laissait passer des interrogatifs/polarité/ordinaux FR/EN (« comment », « how », « does », « why », « who », « non », « now », « premier »…) — artefacts de dataset qui déclenchent de faux routage sur du chatter | le test de garde « Comment vas-tu aujourd'hui ? » → null est repassé vert ; l'accuracy 1M re-mesurée reste 1.00 après retrait |

Le score devient `Σ base × masse` (token non mesuré = exclusif → masse 1).
`predireDomaineLexical` (production) et son miroir d'évaluation appliquent
exactement la même règle.

## 2. Évaluation RÉELLE (exécutée le 2026-11-25, graine 999001)

### 2.1 Routage — 1 000 000 de requêtes exécutées (pas extrapolées)

- **1 000 000 requêtes réellement traitées en 54,1 s (18 499 req/s)**,
  accuracy **1.00 globale et sur chacun des 18 domaines** (~55 500 requêtes
  par domaine ; détail complet dans la preuve JSON).
- Gain mesuré vs v5.0, **même protocole** (graine 999001, générateur 18
  domaines, streaming `train.jsonl`) : 87,06 % → 100 %. Les ~13 % de
  collisions restantes de v5.0 (vente/conseiller_commercial,
  sciences_humaines/recherche_scientifique…) sont résolues par la masse
  d'usage : le token ambigu n'ajoute plus un avantage entier au mauvais
  domaine.
- **Cadrage honnête** : les requêtes sont construites depuis les datasets
  d'entraînement (fenêtres de lecture représentatives, graine distincte
  des graines de génération) — c'est une accuracy **in-distribution** du
  vocabulaire réel des 18 domaines, pas un benchmark d'out-of-distribution.
  Le protocole est inchangé depuis v5.0 : la comparaison 87 → 100 est
  valable, la valeur absolue « 100 % » ne doit pas être lue comme une
  compréhension générale du langage.

### 2.3 Cortex langagier — 900 questions tenues à l'écart (faiblesse assumée)

- ⚠️ Non comparable aux chiffres v5.0 (74,3 % / 15 % / 4,7 %) : depuis le
  commit `801c585` les datasets professionnels sont régénérés (shuffle,
  fenêtres streaming) et le corpus de questions tenu à l'écart a changé.
  La valeur mesurée reste faible : l'appariement par première phrase ne
  généralise pas aux énoncés narratifs longs (GSM8K). Les réponses math
  exactes passent par `moteur_calcul` ; la généralisation profonde du
  cortex langagier est un chantier PHASE 2/3 du plan directeur
  (compréhension sémantique + génération native), pas un acquis.

## 4. Limites honnêtes (inchangées + nouvelles)

1. **Routage 100 % in-distribution** : mesure du vocabulaire réel des 18
   domaines ; la robustesse hors distribution reste à construire (PHASE 2
   — compréhension sémantique).
2. **Cortex langagier tenue à l'écart faible** (26,56 % de hits ; math 0,3 %,
   sciences 1 %) : appariement lexical par première phrase — la vraie
   compréhension passe par le chantier sémantique (PHASE 2), pas par
   l'élargissement de listes de mots-clés.
3. **Échelle physique** (repris du rapport v5) : 10 M × 7 modalités ×
   N domaines = pétaoctets ; sandbox 9,9 Go disque, 2 cœurs, 0 GPU.
4. **Production** : gen3ia.online reste injoignable depuis le sandbox
   (VPS down, préautorisé « continuer et ignorer le service VPS » —
   escalade #163 ouverte, build archivé en release `cd-latest` via la
   relance CD par dispatch).
5. **Quota HF commits** : résorbé par l'upload dossier unique (1 commit au
   lieu de 670).

## 6. Conclusion

v5.1 démontre qu'une **mesure d'usage réelle** (masse par domaine, tokeniseur
exact) résout les collisions lexicales que l'ajout d'ancres ne pouvait pas
résoudre : 87,06 % → 100 % sur 1 M requêtes réelles du même protocole, sans
toucher aux mots-clés noyau curatés ni à aucune API externe. Les faiblesses
honnêtes restent identiques et correctement orientées : la généralisation
(cortex tenu à l'écart) est le travail de la PHASE 2 (sémantique), non un
problème de listes de mots-clés.
