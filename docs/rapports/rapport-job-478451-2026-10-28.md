## 2. Failles & anomalies — détaillées

### F1 — Sonde d'état « auth » mensongère (désinformation publique) — CORRIGÉ
- **Symptôme** : `/api/status` = 503 `degraded`, `auth: not_configured`, affiché
  publiquement sur `/status` (« Authentification : dégradé ») et vu par les
  moniteurs d'uptime.
- **Cause racine** : `authHealth()` (lib/observability/statut-services.ts)
  appelait `getAdminApp()` — compte de service **Firebase Admin**. Or depuis
  la migration R2 (Task 111), AUCUN flux utilisateur n'en dépend :
  - e-mail/mot de passe → comptes scrypt **dans R2** + cookie signé
    (`lib/auth/r2-accounts.ts`, `/api/auth/r2/login|signup`) ;
  - Google → JWT vérifié contre les **certificats publics Google**
    (`lib/firebase/auth-server.ts`, pas d'Admin SDK) ;
  - `getAdminApp()` ne sert plus que des outils admin ponctuels
    (migration Firestore→R2, suppression de compte).
- **Impact réel vérifié** : le login fonctionnait (401 structuré) pendant que
  la page d'état criait « auth dégradé » — exactement le type de
  désinformation interdit par la mission (« sans mal informer un utilisateur »).
- **Correctif** : `authHealth()` sonde désormais la voie réelle (suit la panne
  R2 avec la même raison) ; Firebase Admin retiré de la sonde ; libellé page
  `/status` mis à jour (« e-mail + Google ») ; 2 nouveaux tests vitest
  (auth suit R2 ; auth reste OK sans compte de service).

### F2 — Production gelée malgré des runs CD « verts » (8 commits de retard) — DIAGNOSTIQUÉ, DÉBLOCAGE HUMAIN REQUIS
- **Chaîne d'événements reconstituée** :
  1. 27-10 17:45 — dernier déploiement effectif (b8dd38c, swap SSH réussi).
  2. 27-10 soir → 28-10 — SSH entrant VPS bloqué (fail2ban/PerSourcePenalties,
     observé aussi par les runs #43-#46 et #79-#88 antérieurs).
  3. Le CD publie chaque build sur la release `cd-latest` (canal pull
     « faisant autorité ») puis court-circuite le swap (`continue-on-error`)
     — le run reste **vert**.
  4. Le poller pull (install-pull-mode.sh) n'a **jamais été installé** sur le
     VPS (bootstrap console jamais exécuté) → rien ne récupère les builds.
  5. Le guérisseur (v2/v3) mesure bien l'écart toutes les 30 min mais ses
     deux leviers (armement pull par SSH, dispatch CD) exigent aussi le SSH
     → ticks « success » sans effet.
- **Sondage indépendant** (sandbox, IP externe) : `gen3ia.online:22` →
  **Connection refused** (RST, pas un timeout) — sshd down ou rejet actif ;
  `:443` ouvert. Le déblocage SSH ne peut venir que de la console du
  fournisseur (spaceship.com).
- **Correctifs livrés** (cette itération) :
  - **Escalade visible** : le guérisseur ouvre/commente une **issue GitHub
    dédiée** (« 🚨 Production en retard sur main — intervention console VPS
    requise ») avec la commande console exacte à exécuter, et la referme
    automatiquement dès que `version.json` est aligné — plus jamais une
    production gelée « sans signal » (permission `issues: write` ajoutée).
  - Le rapport CD contient déjà l'avertissement « Production NON basculée ».

### F3 — Faux positifs de l'auditeur de gardes d'auth — CORRIGÉ
- `scripts/audit-gardes-auth.mjs` ne reconnaissait pas :
  - la garde essaim `résoudreIdentitéNœud` (jeton machine timing-safe +
    fail-closed + rate limit — lib/security/noeud-service.ts) →
    `/api/essaim/ondes|resultat` signalées à tort « nues » ;
  - le pattern d'export `export const POST = withAuth(...)` (canonique des
    routes récentes) → `/api/ondes/rpia` signalée à tort ;
  - le webhook de workflow par token (gwtr_<32hex> haché SHA-256, recherche
    par égalité, rate limit, HMAC optionnel) → classé « nue » à tort.
- **Après correctif** : **282 gardées / 19 publiques-par-design / 0 nue**.
- Vérification manuelle des 4 anciens signalements : tous défendus
  correctement (aucune vraie faille d'accès).

### F4 — État sain confirmé (contrôles positifs)
- Webhook Chariow : signature `x-chariow-signature` timing-safe + idempotence
  par claim (itération précédente, re-vérifié dans le code) — Chariow-only
  maintenu (`PAYMENT_PROVIDER=chariow`, autres passerelles → 501).
- Aucun `.env` versionné ; gitleaks allowlist OK ; 7 branches seulement.
- Garde P0 centrale (middleware → `deciderMutationApi`, fail-closed) verte.
- Secrets : **le PAT `ghp_26B1…` reste exposé publiquement (messages de
  tâche cron en clair) — révocation obligatoire, action utilisateur** ;
  idem token HF `hf_OnaO…`. Les correctifs code ne remplacent pas la
  rotation des credentials.
