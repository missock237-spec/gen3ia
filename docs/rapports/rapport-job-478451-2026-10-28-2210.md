## 3. La cause racine du blocage (définitivement identifiée)

Deux pannes indépendantes se renforcent mutuellement :

1. **SSH entrant barré** — OpenSSH ≥ 9.8 (`PerSourcePenalties`) a pénalisé les IP sources des
   dizaines de tentatives SCP du CD (retries 6 × 180 s des runs précédents). Les pénalités vivent
   en mémoire sshd et se rafraîchissent à chaque nouvelle tentative ; le guérisseur ne peut plus
   entrer → aucune réparation à distance possible.
2. **Poller PM2 « updater » inactif** — plus personne ne télécharge la release `cd-latest` côté VPS
   → la prod est gelée sur un vieux build alors que les builds s'accumulent prêts sur GitHub.

Conséquence : le canal SSH (guérisseur, SCP du CD) est mort ET le canal pull (poller) est mort.
La **seule voie d'accès restante est la console web du fournisseur** — d'où le script.

## 4. Ce que fait `fix-definitif-vps.sh` (8 étapes)

1. **Diagnostic** — SHA publié vs SHA en service, état PM2, blacklist, disque, tar résiduel.
2. **Déblocage SSH définitif** — `PerSourcePenalties no` (config principale **+ drop-in
   `00-gen3ia-nopenalties.conf`**), fail2ban unban --all, ufw 22022/tcp, redémarrage sshd
   (purge mémoire des pénalités), validation `sshd -t` avec restauration automatique.
3. **Réinstallation poller pull** — `pull-deploy.sh` v2 + `auto-update.sh` + shim, depuis main
   (HTTPS sortant).
4. **Purge des états bloquants** — backoff `pull-fail.txt`, dé-blacklist du SHA cible (ses échecs
   venaient du canal, pas du build), tar résiduel `/tmp`.
5. **Réparation PM2** — recréation « updater », `pm2 save` + `pm2 startup` (survit aux reboots).
6. **Déploiement immédiat** — premier pull exécuté sur-le-champ (swap atomique + health check +
   rollback via `cd-finisher.sh`).
7. **Watchdog anti-récidive** — timer systemd toutes les 5 min (repli cron) : relance updater/app
   si morts, `pm2 resurrect` après reboot, pull forcé si la prod prend du retard, purge disque ≥ 90 %.
8. **Verdict final** — prod = cible ? health ? updater online ? Affiché dans la console.

## 5. Anomalies détectées et corrigées DANS le script (audit de cette itération)

| # | Anomalie | Gravité | Correctif appliqué |

| 3 | `sshd -t` ne couvrait pas le drop-in ajouté (faux vert possible) | Faible | Validation après écriture du drop-in ; restauration sauvegarde **+** retrait drop-in en cas de rejet |
