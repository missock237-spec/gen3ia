## 4. Enseignement méthodologique — le faux constat « branches: ain] »

En inspectant les déclencheurs, l'agent a « vu » `branches: ain]` dans **cinq workflows** (au lieu de `branches: [main]`) et a entamé une correction. Le remplacement systématique est retourné « 0 occurrence » malgré des affichages cohérents avec le faux constat — contradiction résolue par l'inspection **octet par octet** (`ord()`) : la ligne contient exactement `[91, 109, 97, 105, 110, 93]` = `[main]`. **Le dépôt était sain** ; l'artefact vient du canal de rendu de l'agent, qui avale la séquence `[m` dans les textes affichés (probablement interprétée comme un lien Markdown cassé). Trois conséquences verrouillées :

1. **Aucun dommage** : tous les remplacements étaient des no-ops vérifiés (`git status` propre, les tests verrouillant `branches: [main]` passent).
2. **Discipline nouvelle** : tout constat de « corruption » de littéraux (crochets, accents, guillemets) doit être prouvé par inspection d'octets avant toute modification ; les scripts de correction assemblent les caractères sensibles via `chr()` (persisté dans `/scripts/fix_branches_triggers.py`).
3. **Le vrai défaut détecté ce tick** reste la défaillance des crons — traitée en §3.3/§5.

## 5. Correctif — job `sonder` (commit `fe19087`)

Dans `guerisseur-production.yml`, après `verifier` → `guerir` :

```yaml
sonder:
  name: Déclencher la surveillance synthétique (crons GitHub défaillants)
  needs: [verifier, guerir]
  if: always() && !cancelled()
  runs-on: ubuntu-latest
  timeout-minutes: 3
  steps:
    - name: Dispatch de la sonde HTTP (déclencheur événementiel fiable)
      continue-on-error: true
      ...
      gh workflow run surveillance-production.yml -R "$REPO" --ref main
```

- **`if: always() && !cancelled()`** : la mesure HTTP est la plus précieuse justement quand la réparation a échoué — mais jamais exécutée si le run est annulé.
- **`continue-on-error`** : un dispatch impossible (transitoire) ne rend pas le guérisseur rouge.
- **Permissions** : le workflow dispose déjà de `actions: write` (nécessaire au dispatch) — moindre privilège inchangé.
- **Bouclage impossible** : la surveillance ne dispatch aucun workflow.
- YAML validé par parseur (jobs : `verifier`, `guerir`, `sonder`).
